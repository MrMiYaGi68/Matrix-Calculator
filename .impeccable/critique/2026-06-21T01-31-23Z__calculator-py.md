#### Anti-Patterns Verdict

**LLM assessment**: This does not read as obvious AI slop. The app avoids the common tells: no gradient text, no decorative blobs, no glassmorphism default, no fake hero, no identical marketing card grid, no oversized display typography, no beige/cream monoculture. It reads like a functional Qt desktop calculator with a restrained dark product skin.

The risk is not generic AI landing-page slop. The risk is product-UI strangeness: scientific mode gets cramped, the assistant panel can look as important as the calculator, and a few controls mix icon-only, icon+text and text-only affordances without a fully settled grammar.

**Deterministic scan**: `detect.mjs --json calculator.py ui` returned `[]`. No detector findings.

**Visual overlays**: Browser overlay injection was not available in this session. Visual fallback used fresh `tools/ui_smoke.py` screenshots for compact, expanded, scientific, light, matrix and high-contrast themes.

#### Overall Impression

The interface is now credible and task-focused. It no longer has the earlier broken-keypad impression. The biggest opportunity is to make the scientific and assistant states feel as deliberate as the compact basic calculator: less edge pressure, clearer hierarchy, fewer secondary elements shouting at once.

#### What's Working

1. **The compact basic layout finally has a clear calculator mental model.** Numbers sit together, operators are on the right, and the wide zero key plus decimal/equal placement is familiar.
2. **The color system is restrained enough for a desktop tool.** Graphite uses orange only for operators and primary actions, with red reserved for AC. That is appropriate semantic color, not decoration.
3. **AI is optional and collapsible.** The product promise is local-first calculation, and the UI supports that by letting the assistant disappear.

#### Priority Issues

**[P1] Scientific mode is too vertically compressed**

Why it matters: The scientific screenshot shows the bottom row pressed into the window edge. Even if functionally clickable, it reduces trust because the user sees a dense grid that feels close to clipping.

Fix: Give scientific mode a slightly taller collapsed minimum height, reduce per-button vertical padding only if necessary, or introduce a compact scientific scroll/section strategy. Do not shrink labels below legibility.

Suggested command: `$impeccable adapt scientific calculator layout`

**[P2] Assistant panel competes with the calculator in expanded mode**

Why it matters: In expanded mode the query box and large orange `Berechnen` button dominate the right half. The assistant starts to feel like the product, while the calculator should remain primary.

Fix: Reduce query box visual weight, make examples more compact, and make the primary assistant action less visually equivalent to core arithmetic operators. Keep AI secondary unless the user is actively typing there.

Suggested command: `$impeccable layout assistant panel hierarchy`

**[P2] Button vocabulary is mostly consistent, but not fully settled**

Why it matters: Text buttons (`Rest`, `Basis`, `Wissenschaft`), symbols (`√`, `∛`, `π`), icons (`⌫`, settings), and icon+text buttons coexist. That is acceptable in a calculator, but a few controls feel like they belong to different systems.

Fix: Standardize when a button uses symbol-only versus localized text. Use symbol-only for universal operations and text for modes/actions. Ensure tooltips carry the localized explanation.

Suggested command: `$impeccable clarify button labels and tooltips`

**[P3] Active/selected states are functional but visually similar to ordinary raised buttons**

Why it matters: `Basis`, `Wissenschaft`, and `KI ausblenden` use a similar raised treatment. Users can understand it, but the selected state does not snap into place as quickly as best-in-class product UI.

Fix: Define one active-state grammar across segmented controls and toggles: same border weight, same fill logic, same focus/checked distinction.

Suggested command: `$impeccable polish active states`

#### Persona Red Flags

**Alex (Power User)**: The compact basic calculator is efficient, but scientific mode density makes scanning slower. Alex will rely on keyboard input, yet the UI does not visibly teach shortcuts beyond tooltips.

**Jordan (First-Timer)**: Jordan can start with basic arithmetic quickly. The assistant panel examples help, but expanded mode may make them wonder whether they should type natural language instead of using the calculator.

**Samira (Accessibility-Conscious User)**: High-contrast theme exists, which is strong. The main red/orange states are not color-only because labels remain visible. The cramped scientific bottom row is the main visual risk.

#### Minor Observations

- Light theme is clean and readable, but the orange operator column is very saturated relative to the pale surface.
- `Rest` is clearer than `mod` for German users, but it makes the scientific/basic label system mixed. Tooltip consistency matters here.
- The settings icon button is compact and standard; it does not feel decorative.
- The app avoids most obvious AI-generation tropes.

#### Questions to Consider

- Should expanded mode feel like “calculator plus optional assistant” or like a two-pane math workspace?
- Is scientific mode meant to fit without scrolling at this exact compact height, or should it be allowed more vertical room?
- Which controls should be universal symbols, and which should be localized words?
