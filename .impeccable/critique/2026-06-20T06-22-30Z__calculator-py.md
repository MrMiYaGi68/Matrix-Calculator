## Overall Impression

The app now feels like a usable desktop calculator with optional AI, not an AI assistant pretending to be a calculator. The compact state is the strongest surface. The expanded state is functional and calmer, but still feels like a stack of panels rather than a guided assistant workflow.

## What's Working

- The compact state is much clearer: `Lokal`, `DEG`, `Basis`, `Wissenschaft`, `Verlauf`, and `KI öffnen` form a more understandable top area.
- Theme moved to settings, which removes a non-task decision from the main calculator flow.
- The expanded AI panel is quieter: `Berechnen` no longer competes with orange calculator operators.

## Priority Issues

**[P1] Expanded AI panel still has too many equally weighted containers**

Why it matters: The assistant side has status, input, calculate, preview, settings, ChatGPT, output, and clear-chat as separate boxed regions. Users can understand it, but it feels procedural rather than fluid.

Fix: Treat the assistant as one flow: question input, answer, secondary actions. Merge or soften preview/status, make settings and ChatGPT tertiary, and let answer output own the lower half.

Suggested command: `$impeccable layout Matrix Calculator assistant panel`

**[P1] Error and recovery states need designed surfaces**

Why it matters: A calculator lives or dies on trust. Invalid expressions, ambiguous natural-language questions, local parser uncertainty, missing API key, and online failures need clear recovery paths.

Fix: Add specific inline states for invalid expression, ambiguous AI query, local-not-sure, API missing, and online transfer declined. Each state should say what happened and what the user can do next.

Suggested command: `$impeccable harden Matrix Calculator recovery states`

**[P2] Top control row is improved but still too equal**

Why it matters: `Basis`, `Wissenschaft`, `Verlauf`, and `KI öffnen` still look similar in weight. Mode, history, and assistant are different categories.

Fix: Make Basic/Wissenschaft a tighter segmented unit, make Verlauf a secondary utility button, and keep KI öffnen as a distinct side-panel action.

Suggested command: `$impeccable layout Matrix Calculator top controls`

**[P2] Some visible labels still rely on learned meaning**

Why it matters: Tooltips help, but users do not discover all tooltips before calculating. `Ans`, `e`, `cbrt`, duplicate parentheses, and compact `◂ KI` can still slow recognition.

Fix: Keep expert labels where necessary, but improve grouping and visible semantics. In expanded mode, prefer `KI ausblenden` where width allows.

Suggested command: `$impeccable clarify Matrix Calculator labels`

**[P3] Empty states explain location, not value**

Why it matters: “Antworten erscheinen hier” and “Live-Erkennung erscheint hier” tell users where output appears but not how to start well.

Fix: Use short examples or next actions, especially in the assistant panel before the first query.

Suggested command: `$impeccable onboard Matrix Calculator assistant empty states`

## Persona Red Flags

**Power Calculator User**: The compact surface is now fast enough, but top controls still take more visual space than a power user needs. Keyboard shortcut visibility is still mostly hidden in tooltips.

**Scientific User**: Tooltips help, but function grouping and labels such as `cbrt`, `Ans`, and `e` still assume familiarity. The user can proceed, but not with full confidence on first use.

**Privacy-Sensitive Local User**: `Lokal` is a good signal. The expanded panel still needs sharper local vs ChatGPT/API boundaries near the ChatGPT button and API settings path.

## Minor Observations

- The detector warning is unchanged and acceptable for this product context.
- Focus styling is strongest on the assistant input; button focus states are less explicit.
- Settings dialog localization is not fully consistent for non-German/non-English labels.
- The compact view is now stronger than the expanded view.

## Questions to Consider

- Should the assistant panel feel like a chat, a math worksheet, or a command form?
- What are the five most common failure states users actually hit, and can each be recovered in one click?
- Does `Verlauf` need equal visual weight to mode and AI, or should it become a quieter utility?
