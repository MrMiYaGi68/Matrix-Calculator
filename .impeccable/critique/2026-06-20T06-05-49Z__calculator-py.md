## Anti-Patterns Verdict

**LLM assessment**: This does not look like generic landing-page AI slop. It does have product-slop symptoms: generic dark tool palette, orange accent doing too many jobs, rounded block controls everywhere, and a feature-inventory layout where capabilities are visible before their relationship is clear.

**Deterministic scan**: The detector found 1 warning:

- `single-font`, warning, `calculator.py:1088`, detected DejaVu Sans as the only font.

This is mostly a false positive for a product UI. Product-register guidance allows one familiar sans family, and the calculator display uses mono fonts in `ui/theme.py` for expression/result labels. The warning still points at a mild issue: typography is not doing much to separate app chrome, calculator data, assistant copy, and metadata.

**Visual overlays**: Skipped. This is a PySide6 desktop app, not a browser DOM target, so Impeccable browser overlay injection is not applicable. Visual evidence came from OS screenshots of collapsed and expanded states.

## Overall Impression

The calculator is usable and serious. The expanded AI panel proves the product has more depth than the compact startup state suggests. The biggest opportunity is to make the calculator feel like one coherent tool: calculation first, AI second, settings/history/theme third.

## What's Working

- The core calculator surface is recognizable: large result display, clear keypad, AC/CE, operators, memory, and scientific mode.
- Target sizes are good for desktop. Buttons are large enough for repeated use and do not feel fragile.
- The expanded AI panel has a real workflow: input, local mode status, live recognition, calculate action, settings, ChatGPT, answer area, and clear chat.

## Priority Issues

**[P1] AI unfold control is semantically wrong**

Why it matters: In compact mode, the blue `▶` button can be read as "calculate" or "run", especially in a calculator. Users can miss that it opens the AI side panel.

Fix: Replace it with a side-panel affordance: `KI öffnen`, `Assistent`, or a chevron/sidebar icon with text at normal widths. Reserve play icons for executing a query inside the expanded assistant.

Suggested command: `$impeccable clarify Matrix Calculator AI toggle`

**[P1] Visual hierarchy treats too many controls as peers**

Why it matters: The result and input should dominate. Instead chips, theme, history, layout, AI toggle, keypad, and display all have similar weight.

Fix: Demote theme selection to settings, make layout mode a compact segmented control, reduce chip prominence, and let expression/result/keypad own the primary surface.

Suggested command: `$impeccable layout Matrix Calculator main window`

**[P2] Expanded AI panel is useful but visually heavy**

Why it matters: Once unfolded, the assistant becomes almost as dominant as the calculator. That is fine when AI is the task, but it should still feel secondary to calculation unless the user explicitly shifts modes.

Fix: Give the assistant a clearer hierarchy: status as quiet metadata, query field as primary, answer area as content, secondary actions below. The orange `Berechnen` button is too visually loud compared with the calculator equals/operator system.

Suggested command: `$impeccable quieter Matrix Calculator assistant panel`

**[P2] Scientific/basic mode discoverability is weak**

Why it matters: `Wissenschaft` is not a clear state model. Users need to know whether they are in Basic or Scientific and what changed.

Fix: Use `Basic | Wissenschaft` as a segmented control or a stable mode switch with explicit active state.

Suggested command: `$impeccable clarify Matrix Calculator mode controls`

**[P2] Expert functions need recognition support**

Why it matters: `mod`, `Ans`, `sqrt`, `cbrt`, and future scientific labels are efficient for experts but opaque for casual users.

Fix: Add consistent tooltip copy, clearer labels where space permits, and a lightweight functions/help affordance in scientific mode.

Suggested command: `$impeccable harden Matrix Calculator scientific controls`

## Persona Red Flags

**Power User / Engineer**: Keyboard support exists, but shortcuts are not visible in the primary UI. The user can probably move fast after learning it, but the interface does not advertise its efficiency.

**First-Time Scientific Calculator User**: The top-level `Wissenschaft`, `Graphite`, `Verlauf`, and `▶` row mixes mode, theme, history, and AI. That row makes the user decide between unrelated concepts before they have entered a calculation.

**AI-Cautious Local-First User**: The expanded panel says local mode is active, which is good. The collapsed state says "KI-Assistent rechts" but does not reassure what stays local before opening.

## Minor Observations

- `M 0` looks active even when memory is empty.
- Orange is used for brand emphasis, memory, operators, equals, and assistant primary action.
- The settings gear disappearing from the header when expanded can feel inconsistent, even though settings appears in the assistant panel.
- The app window starts compact, but the subtitle already references the hidden assistant. That is accurate but not actionable.

## Questions to Consider

- Should AI feel like a side tool attached to the calculator, or a second equal workspace?
- Is theme switching important enough to live in the main toolbar?
- Would the compact state be stronger if it showed only calculation controls plus one clear "Open assistant" action?
